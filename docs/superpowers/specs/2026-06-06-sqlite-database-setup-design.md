# SQLite Database Setup Design

**Date:** 2026-06-06
**Branch:** app/mule-travel-packing-app

## Overview

Set up a local-first SQLite database layer for the Mule travel packing app using OPS SQLite as the native engine, PowerSync as the sync layer (local-only mode for now), and Drizzle ORM for type-safe queries and migrations.

The stack is designed so that adding a PowerSync backend later requires only a single config change — no hooks, schema, or component code changes needed.

## Architecture

### Startup Flow

1. `DatabaseProvider` mounts inside `AppLayout`
2. Creates PowerSync instance with OPS SQLite driver, no backend URL
3. Migration runner checks `__drizzle_migrations` table, executes any unrun SQL files from `src/database/migrations/`
4. `powerSync.connect()` starts the local DB (sync is a no-op without a backend)
5. Drizzle client and PowerSync instance are available via context

### Adding Sync Later

When a PowerSync backend is ready, pass a `backendConnector` to the PowerSync instance in `src/database/client.ts`. No other changes required.

### Contexts

- `DatabaseContext` — exposes the typed Drizzle `db` client
- `PowerSyncContext` — exposes the PowerSync instance for reactive queries and eventual sync status

## Schema

All primary keys are client-generated UUIDs — required for PowerSync's CRDT-based sync. Booleans are stored as `integer` (0/1), SQLite has no native boolean type. JSON arrays are stored as `text`.

`trip_items.name` and `packing_list_items.name` are denormalized copies of the item name — stored even when `inventory_item_id` is set, so display never requires a join to `inventory_items`.

## Types

Each feature's `types.ts` exports inferred Drizzle types using the `Entity` suffix to avoid collisions with component names:

```ts
// trips/database/types.ts
export type TripEntity = typeof trips.$inferSelect
export type NewTripEntity = typeof trips.$inferInsert
export type TripLocationEntity = typeof tripLocations.$inferSelect
export type NewTripLocationEntity = typeof tripLocations.$inferInsert

// lists/database/types.ts
export type PackingListEntity = typeof packingLists.$inferSelect
export type NewPackingListEntity = typeof packingLists.$inferInsert
export type PackingListItemEntity = typeof packingListItems.$inferSelect
export type NewPackingListItemEntity = typeof packingListItems.$inferInsert

// inventory/database/types.ts
export type InventoryItemEntity = typeof inventoryItems.$inferSelect
export type NewInventoryItemEntity = typeof inventoryItems.$inferInsert

// categories/database/types.ts
export type CategoryEntity = typeof categories.$inferSelect
export type NewCategoryEntity = typeof categories.$inferInsert
```

## Hook Patterns

### Read hooks — typed output

```ts
useTrips(): { data: TripEntity[]; isLoading: boolean; error: Error | null }
useTrip(id: TripEntity['id']): { data: TripEntity | null; isLoading: boolean; error: Error | null }
useTripLocations(tripId: TripEntity['id']): { data: TripLocationEntity[]; isLoading: boolean; error: Error | null }
```

Read hooks use PowerSync's `useQuery()` — components re-render automatically when underlying data changes.

### Write hooks — typed input and output

```ts
useCreateTrip(): (input: NewTripEntity) => Promise<TripEntity>
useUpdateTrip(): (id: TripEntity['id'], input: Partial<NewTripEntity>) => Promise<TripEntity>
useDeleteTrip(): (id: TripEntity['id']) => Promise<void>
```

Write hooks call Drizzle mutations directly. PowerSync propagates changes to all active `useQuery` subscribers automatically.

## Migrations

- `drizzle-kit generate` writes SQL files to `src/database/migrations/`
- Migration runner executes unrun files at startup via PowerSync's connection
- Migration state tracked in `__drizzle_migrations` table
- Never use `drizzle-kit push` — it is destructive and unsafe across app versions

---

## Error Handling

- `DatabaseProvider` renders an error boundary if DB initialization or migration fails
- Read hooks surface errors via `{ error: Error | null }` — no throwing
- Write hooks throw on failure — callers handle via try/catch
- No global error swallowing

---

## Testing

- `queries.ts` files get integration tests against an in-memory OPS SQLite instance
- Hooks get unit tests with a test `DatabaseProvider` wrapper
- Migration runner gets a focused test verifying all migrations apply cleanly from zero
- PowerSync itself is not tested — it is a third-party library
- Test files live alongside their subjects (`queries.test.ts`, `useTrips.test.ts`)
